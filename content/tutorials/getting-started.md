# 完成你的第一个可验证任务

::: tip 学完可以做到
让 Codex 在一个安全文件夹里完成任务，并判断结果是否真的可用。
:::

## 01 选择最顺手的入口

想直接操作本地文件，可以从桌面 App 开始；习惯终端或编辑器的开发者，可以使用 Codex CLI 或 IDE 扩展。第一次不需要同时安装所有入口。

## 02 准备一个低风险任务

新建一个单独的练习文件夹，选择你能判断结果对错的小任务，例如创建简单网页、整理 Markdown 文档，或解释一段熟悉的代码。

## 03 把完成标准说清楚

告诉 Codex 目标、相关上下文、不能触碰的边界，以及什么现象代表任务完成。无需追求复杂提示词，信息足够即可。

## 04 让它执行并验证

允许 Codex 阅读文件、实施修改并运行检查。完成后查看实际文件、预览或测试结果，不要只看对话里的完成说明。

## 直接复制这个任务结构

```text
请在当前文件夹创建一个简单的个人记账网页。

目标：可以新增和删除账目，并显示本月支出总额。
范围：只修改当前文件夹，不安装不必要的依赖。
边界：不要访问文件夹外的文件，不使用真实账户数据。
完成标准：页面可以打开，新增和删除后总额正确更新。

完成后请启动页面进行检查，并说明修改了什么、如何验证。
```

## 任务结束前检查

- 实际文件已经生成或修改。
- 页面、命令或测试能够运行。
- 结果符合开始时写下的完成标准。
- 没有混入无关改动或敏感信息。

::: warning 第一次先保持权限简单
不要提供 API Key、密码或真实用户数据，不要把生产环境作为练习任务，也不要批准自己不理解的高风险操作。
:::
