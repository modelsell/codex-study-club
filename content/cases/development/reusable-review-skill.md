# 把重复的代码审查流程沉淀成 Skill

## 可以直接使用的任务描述

```text
基于团队现有审查规范创建一个代码审查 Skill。
它需要先读取差异和相关测试，再按严重级别输出可定位到文件行号的问题；
没有问题时说明残余风险。
```

## 关键过程

1. 收集团队现有规范、常用命令和输出格式。
2. 只把稳定、可重复的步骤写进 Skill。
3. 用真实变更分别验证有问题和无问题两种情况。

## 如何判断完成

- 问题包含代码位置和证据。
- 严重级别保持稳定。
- 没有问题时不会捏造发现。

## 验证结果

同一组审查规则可以在不同代码变更上重复执行，并保持一致的输出结构。
