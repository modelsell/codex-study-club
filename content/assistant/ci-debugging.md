先不要让 Codex 根据一小段报错直接修改。更可靠的顺序是：

1. 提供运行链接、attempt、提交 SHA、失败 job/step、实际命令及关键错误上下文；日志先脱敏。
2. 先读工作流配置，区分依赖环境、测试断言、生成文件和服务启动问题；日志不足时不猜根因。
3. 限制修改范围，再实施最小修复。
4. 运行与失败环境一致的验证。
5. 审查差异，按本次提交 SHA 检查远端结果；本地通过、CI 成功和生产可用分开记录。

在本站仓库，`npm run check:content` 可只读检查源内容与生成快照是否一致；发现过期后重新生成并审查，不要手改生成 JSON 或删除检查。它不代表其他项目也有同名命令。

涉及密钥、用户数据或生产地址时，粘贴前先脱敏。
