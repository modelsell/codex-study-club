# PR Chat 与行内编辑：在 Codex 内完成审查跟进

> 来源核对：OpenAI Developers 于 2026 年 7 月 17 日在 X 发布了 [PR Chat 与行内代码编辑演示](https://x.com/OpenAIDevs/status/2077902662973190570)。

## 新增的两个关键动作

- **PR Chat**：围绕一个指定 Pull Request 提问，Codex 会保留这个 PR 的上下文。
- **行内代码编辑**：把审查反馈交给 Codex，直接查看它提出的补丁，并选择编辑、接受或拒绝。

这让“理解 PR”和“跟进修改”可以留在同一个上下文里，但最终判断仍然由你完成。

## 推荐的审查顺序

1. 先让 Codex 总结 PR 的目标、改动范围和验证方式，不要立即改代码。
2. 让它按正确性、兼容性、安全性和测试缺口检查高风险位置。
3. 对确认需要处理的行留下具体反馈，再让 Codex 生成补丁。
4. 在行内检查补丁；需要时先编辑，不合适就拒绝，不要把“已生成”当成“已正确”。
5. 接受补丁后运行与 PR 相同的测试、lint 或构建命令，并重新查看完整 diff。

## 适合交给 PR Chat 的问题

```text
请先不要修改这个 PR。

1. 用三句话说明它改变了什么行为。
2. 找出最可能产生回归的调用路径。
3. 检查新增测试是否覆盖失败分支和边界输入。
4. 每个结论都引用具体文件和代码位置。
5. 区分确定问题、需要作者确认的问题和非阻塞建议。
```

## 仍然需要人工把关的地方

PR 上下文能够减少重复解释，但不能替代仓库约定、CI 结果和产品判断。接受行内补丁前，至少确认它没有扩大修改范围、隐藏失败分支，或用测试数据掩盖真实错误。
