# 第一个 Codex 任务：做一张可验收的学习卡片

::: tip 最后核对
官方资料最后核对日期：2026-09-27。任务入口参考[快速开始](https://learn.chatgpt.com/docs/quickstart)，组织方式参考[项目文档](https://learn.chatgpt.com/docs/projects)，提示设计参考[官方 Prompting](https://learn.chatgpt.com/docs/prompting)。下文是供读者执行的练习，没有在本轮重新运行客户端生成这张卡片，不代表已经替读者完成。
:::

这次只做一张“我的 Codex 学习卡片”：包含准备、执行、验收三个部分，在本地浏览器打开即可。内容由你提供，既不用先配置第三方 API，也不用一开始就处理联网资料、数据库和部署。

## 1. 选一个空目录

在文件管理器中创建空文件夹，例如 `codex-first-task`。在桌面客户端选择 Codex，将该文件夹关联为本地项目，并确认新任务使用 **Local** 位置。目录或运行位置不清楚时，先看[上一章](./05-app-overview.md)。

不要选择放有重要文件的目录来试验。先让 Codex 只读列出目录内容；如果并非空目录，换到自己的练习目录后再开始。

## 2. 给出结果和验收标准

可以复制以下提示；其中的文案是练习要求，不需要查找外部历史资料：

```text
在当前空目录中创建一张中文学习卡片，只新增 index.html。
页面标题为“我的 Codex 学习卡片”，包含三个部分：
准备：选对目录，说明目标。
执行：先完成一个小任务。
验收：打开结果，逐项检查。

CSS 放在 HTML 内，不安装依赖，不使用外部字体、图片或脚本。
页面在手机窄屏和桌面上都能阅读，标题层级清楚，不出现横向滚动。
不要提交、推送或部署。

完成后列出新增文件、做过的检查和我应如何打开页面。
如果你没有实际打开浏览器，就明确说明尚未验证显示效果。
```

这段提示把“做什么”和“怎样判断做完”放在一起。无需指定每一行代码；文件范围、页面文案和验收要求已经足够明确。

## 3. 自己检查结果

找到实际生成的 `index.html`，用浏览器打开；也可以使用客户端提供的文件预览入口。如果它没有成功打开，不要把聊天里的代码块当成已经生成并可用的文件。

| 检查项 | 通过标准 |
| --- | --- |
| 文件 | 练习目录中存在 `index.html`，没有额外依赖或无关文件 |
| 文案 | 页面标题与三个部分的文字完整、顺序正确 |
| 阅读 | 桌面和约 375 像素宽的窗口都能阅读，没有横向滚动 |
| 独立性 | HTML 不引用外部字体、图片、脚本，离线重新打开仍能显示 |
| 记录 | Codex 区分了已执行与未执行的检查，你能复述尚未确认的项 |

浏览器能显示文件，只证明本地结果可用；它没有因此发布到互联网。第一轮不要求提交或部署，也不要把“文件创建成功”“浏览器打开成功”“页面效果合格”合成一个未经核实的结论。

## 4. 只改一个问题，再复查

例如手机宽度下文字拥挤，可以继续发送：

```text
375 像素宽时卡片内容过于拥挤。请只修改 index.html 的布局和间距，
保持标题与三段文案不变，不增加依赖。
完成后说明具体修改，并复查窄屏是否出现横向滚动；未实测就标明。
```

每轮都对照页面检查变化。若生成过程失败，保留报错和现有文件，让 Codex 先解释失败阶段；不要为了“重来”直接清空整个项目。

## 5. 留下可继续的记录

完成后在笔记中记录：目标、交付文件、通过的检查、未完成事项。继续同一个结果时可以留在当前任务；另开任务时主动提供这份记录，并核对工作目录。项目里的文件可作为材料，不能假定全部旧对话会自动传入新任务。

想练习真实仓库里的修改与构建，可以继续[第一次内容贡献](/cases/first-content-contribution)；想让任务描述更准确，进入[任务设计](./07-task-design.md)。
