# CLI 选项与命令：选对目录、只读检查与恢复任务

适合已经安装 Codex CLI、想读懂陌生仓库，却不确定命令会在哪个目录执行、会不会修改文件的读者。本章的目标是一张带文件依据的“启动与验证命令表”，再加一份能正确续接任务的记录。

**验证范围**：2026-10-16 已核对下列官方原文。本站本次未完成 CLI 启动与任务执行验证，不能把示例写成实测成功；读者应先核对自己安装的版本与帮助输出。

## 先核对本机版本和帮助

在终端逐条运行，确认前一条正常返回后再继续：

```bash
codex --version
codex --help
codex exec --help
codex resume --help
```

记录版本、操作系统和准备使用的子命令。参数不存在、命令卡住或没有正常返回时，先保留错误与退出状态，停止后续练习，回到[CLI 安装与首次验证](./10-cli-installation.md)核对安装入口。不要把“命令存在”当成“客户端能正常工作”。

## 先选任务入口，再选目录与权限

| 你要做的事 | 入口 | 本章用法 |
| --- | --- | --- |
| 边看结果边补充条件 | `codex` | 交互式阅读仓库 |
| 一次输出固定结构的答案 | `codex exec` | 无交互的命令表整理 |
| 延续某个已有任务 | `codex resume` | 核对会话与工作区后继续 |

`--cd` 显式指定任务目录。下文的 `./your-repo` 是占位路径，先替换成你自己的、已授权阅读的仓库路径；有空格时保留引号。[CLI 参数参考](https://learn.chatgpt.com/docs/cli/reference)

先启动只读交互任务：

```bash
codex --cd "./your-repo" --sandbox read-only --ask-for-approval on-request
```

这两个权限选项各管一件事：`read-only` 设置模型生成命令的沙盒边界；`on-request` 控制需要越过边界时的审批。沙盒内允许的命令可以直接运行，**不会每条命令都询问**。本练习若请求写文件或扩大权限，先查看原因，不以完成这张表为由放宽权限。[官方审批与沙盒说明](https://learn.chatgpt.com/docs/agent-approvals-security)

## 复制这一条只读任务

先在会话中查看 `/status`，确认目录与权限符合预期，再发送：

```text
只读梳理当前仓库的启动和验证方式，不修改文件。
先确认当前目录、分支和已有改动；不暂存、清理或撤回任何改动。
阅读 AGENTS.md、README 和存在的项目配置，缺失就写“未找到”。

请输出一张表：用途 | 命令原文 | 依据文件与位置 | 前提 | 是否实际运行。
用途只包含：安装、本地启动、构建、测试、格式或类型检查。
只记录文件中有依据的命令；冲突写清双方出处，不猜测正确答案。
本轮不要执行安装、启动、构建或测试，不调用外部服务。
最后列出尚未确认的条件，以及下一步最小验证建议，然后停止。
```

这份提示词要求的是**命令清单**。列出 `npm run build` 并不代表构建通过；“是否实际运行”一栏在本练习应明确写“未运行”。非 Node 项目也应按实际配置填写，不能套用示例命令。

需要无交互输出时，可在核对本机帮助后使用下面的短版：

```bash
codex exec --cd "./your-repo" --sandbox read-only -c 'approval_policy="never"' "只读核对 README 和存在的项目配置；列出安装、启动、构建、测试命令及文件依据。不要修改文件、运行这些命令或调用外部服务。缺少依据就写未确认，最后列出未验证项。"
```

`never` 表示不弹出审批请求，**不表示获得全部权限**；这里仍保留只读沙盒。操作受阻时应记录未完成项，不反复重试或改成更宽权限。`exec` 的配置覆盖与非交互入口见[CLI 参数参考](https://learn.chatgpt.com/docs/cli/reference)，权限组合见[审批说明](https://learn.chatgpt.com/docs/agent-approvals-security)。

## 续接任务：先确定是哪一条会话

任务开始时记录会话标识、仓库目录和起始提交；收尾时补充已完成与未完成项。没有保存起始状态就标为未知，不能用结束状态补写。可以使用[任务检查点模板](/templates/codex-task-checkpoint.md)。恢复时把占位符替换成目标会话的 UUID 或准确名称：

```bash
codex resume "SESSION_ID" --cd "./your-repo" --sandbox read-only
```

当前官方说明中，`--last` 选择当前目录最近会话，增加 `--all` 会把其他目录也纳入选择。几个任务并行时，直接使用已核对的标识更容易确认目标。显式 `--cd` 会覆盖恢复时的目录选择；指定之前应确认这就是目标任务的仓库。[恢复会话说明](https://learn.chatgpt.com/docs/cli/reference)

恢复后先查看状态，再发这段核对要求：

```text
先只读核对当前目录、分支、提交和工作区改动是否与交接记录一致。
对照上一阶段结论，列出仍成立、已变化和缺证据的项目。
如会话或仓库不匹配，停止并说明差异；匹配后只提出下一步，不立即修改。
```

恢复历史对话不会替你确认磁盘状态。期间他人可能改过代码，先核对再继续；阶段总结也不是测试记录。

## 正在运行时：纠偏和排队分开

在当前官方 **CLI** 按键说明中：

- **Enter**：将补充指令送入当前轮，适合纠正当前任务的范围。
- **Tab**：把后续提示词、Slash Command 或 Shell 命令排到下一轮。

因此，“本轮不要运行测试，只整理已有配置”属于当前轮纠偏；“完成后再解释测试目录结构”可以排队。输入后查看界面状态和后续响应，不因暂时没有回答就重复发送。已排队的 Slash Command 要等到实际执行时才解析，菜单或错误也可能那时才出现。这些是 CLI 的说明，不能直接套到 IDE 或桌面端；自定义按键还需核对本机设置。[官方命令与快捷键](https://learn.chatgpt.com/docs/developer-commands)

本练习只需认识以下几个 Slash Commands，实际可用项以输入 `/` 后的菜单为准：

| 命令 | 用途 |
| --- | --- |
| `/status` | 查看会话配置与用量等状态，核对执行环境 |
| `/permissions` | 查看或调整权限；本练习保持只读 |
| `/copy` | 复制最近一次已完成的输出 |
| `/exit` | 退出 CLI |

以上来自[官方 Slash Commands 列表](https://learn.chatgpt.com/docs/developer-commands)。Slash Command 在 Codex 输入框内使用；终端里的 `codex --help` 是另一类命令。

## 拿到什么，怎样验收

练习结束应有命令表和续接记录，而不是一句“已理解仓库”。逐项检查：

1. 抽查两条命令，回到所引用的文件确认名称与内容一致。
2. 未执行的安装、构建和测试明确标为未运行；没有把文件推断写成成功结果。
3. 对照任务开始时的工作区记录，确认没有新增改动；原有修改仍保留。可参照[完整变更验收方法](/cases/codex-finished-but-not-verified)，不要只看一个空 diff。
4. 续接记录包含可辨认的会话、仓库和下一步，缺失信息明确标出。

若读不到文件，检查目标目录和可读范围；若表中出现不存在的命令，让它逐项补原文依据；若需要安装依赖才能进一步确认，就将其列为下一阶段任务。本章没有验证自动化稳定性、跨系统按键差异或恢复后任务成功率。
