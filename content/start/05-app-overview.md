# 认识 Codex 桌面：项目、任务与运行位置

::: tip 最后核对
官方资料最后核对日期：2026-09-27。本文按官方桌面、项目和运行环境文档整理；没有逐项实测所有系统和账号。按钮名称与可见功能以你的客户端版本、账号和组织设置为准。
:::

## 找到处理代码的入口

当前[官方快速开始](https://learn.chatgpt.com/docs/quickstart)把桌面入口写为 ChatGPT desktop app。处理代码库与开发任务时，从 ChatGPT 下拉菜单选择 **Codex**，然后开始新任务。旧版截图中的菜单位置不能保证和你面前的版本一致。

先确认三个信息：选中的是 Codex、任务关联了目标项目、项目包含你准备操作的文件夹。安装和登录问题可回到[桌面安装](./02-app-installation.md)。

## 项目整理文件，任务承载一次工作

项目适合持续使用同一批文件和背景的工作；任务则围绕一个明确结果展开，例如解释目录、修正文案或定位一项报错。一次性提问也可以不放进项目。

本地项目可以关联文件夹；官方当前也支持为本地项目添加多个文件夹，并指定主文件夹。新任务默认从主文件夹开始，Git 操作和项目约定的自动发现也以主目录为基础。因此打开项目后应核对当前目录，不能只看项目名称。[官方项目说明](https://learn.chatgpt.com/docs/projects#use-local-projects-for-folders-and-codebases)

同一项目中的任务可以访问相关文件，但不要假定新任务已经知道另一个任务的全部对话。把长期约定写进项目文档，需要继续工作时提供当前目标、已完成结果与未完成事项。

## 确认修改发生在哪里

| 运行位置 | 文件在哪里变化 | 开始前核对 |
| --- | --- | --- |
| Local | 当前项目目录 | 是否有未保存或未提交的工作 |
| Worktree | 独立的 Git 工作树 | 分支、路径以及后续如何审查和整合改动 |
| Cloud | 已配置的远端环境 | 仓库、依赖与结果如何取回 |

Local 与 Worktree 都在本机运行，Cloud 使用远端环境。一个项目并不意味着所有任务都修改同一个目录。上述含义来自[官方运行环境说明](https://learn.chatgpt.com/docs/environments/modes)。第一次练习可选空的本地目录，先把位置确认清楚。

## 读懂一次任务的结果

| 你要确认的事 | 查什么证据 |
| --- | --- |
| 是否选对材料 | 任务中的项目/文件上下文，以及实际读取的文件名 |
| 是否修改了文件 | 文件面板、改动 diff 或对应文件的实际内容 |
| 是否执行了验证 | 命令、退出状态与结果，而不仅是“已完成”一句话 |
| 是否还需要处理 | 错误、待回答问题、权限请求与明确的未完成事项 |

先理解权限提示对应的具体操作，再决定是否允许。项目组织与沙盒权限是不同层次；把任务命名为“只读”或在提示中写“只读”，都不能代替实际权限配置。相关说明可从[项目文档](https://learn.chatgpt.com/docs/projects)进入沙盒文档继续阅读。

## 设置按需查阅

无需先调整所有开关再开始练习。需要扩展能力时，使用相应的官方文档：

- 修改模型供应商或配置字段：[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)；站内有[第三方 API 配置说明](./04-third-party-api.md)。
- 使用外部工具：[插件与连接](https://learn.chatgpt.com/docs/plugins)；先检查该插件的登录方式与权限。
- 查找文件预览和桌面能力入口：[桌面应用说明](https://learn.chatgpt.com/docs/app)。

本章不再用旧截图列出所有设置，也不把某个权限、速度或套餐组合当成所有新手的默认选择。

## 两分钟自检

在准备练习的项目中发送：

```text
先只读检查这个项目，告诉我当前任务的工作目录、看到的文件名，
以及你从现有项目文档中找到的运行或验证命令。
找不到就说明没有，不要猜测。暂时不安装依赖、不修改文件。
```

将回答与自己的文件夹对照。目录不符时先纠正任务上下文；能读到正确材料后，再进行[第一个可验收任务](./06-first-task.md)。
