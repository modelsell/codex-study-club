# 选题、验证与引入门槛

2026-11-01 根据用户要求建立。覆盖最新 Agent 产品、Codex、Claude Code 的新闻、技巧与案例；日常发布已获授权，以下是必须执行的质量门槛。

## 先判断谁会需要

用户于 2026-11-01 追加要求：持续调研其他 Agent 产品。选题按读者任务组织，覆盖编程、团队值守、浏览器操作、资料研究等；不把 Codex / Claude Code 设为必选条件，也不把某个新品牌设为日更配额。原型、SDK、托管服务和正式产品分别说明。

新选题入选前，至少阅读当日官方原文及两个独立需求信号。需求信号可以来自一手 GitHub Issue/讨论、开发者社区、Reddit、X 或本站实际反馈；优先近 30 天，至少一份应在该窗口内。同一作者跨平台转载、引用同一原帖的新闻不重复计数。两个官方发布页面不能充当两份用户需求。

在 [TOPICS](TOPICS.md) 记录每份原始链接、原发布日期（无法核对则明确写未知）、实际读取日、来源性质、目标读者、遇到的损失、文章能交付什么，以及引入或暂缓理由。需求信号支持编辑判断，不能证明一定有阅读量、故障发生率或本站读者收益。没有本站访问证据时，不写热门、必看或用户增长结论。

已有页面的事实纠错、已复现的本站故障修复和必要安全维护可以直接处理，记录具体错误与验证；不为满足来源数量延误修复。新产品介绍、常青技巧和新案例仍须过选题门槛。没有值得引入的新内容就修订旧文、补验证或保持不发布，不能凑日更。

## 再验证文章中的承诺

| 类型 | 发布前必须取得 | 不能声称 |
| --- | --- | --- |
| 产品动态 | 当日原始发布说明与当前官方文档；版本、发布日期、适用入口；冲突信息已解决或明确降级 | 读完发布说明就等于升级、故障恢复或性能实测 |
| 使用技巧 | 最小输入、前提、实际命令/步骤、预期与实际结果、失败分支；产物可读/可运行 | 仅静态文件检查就证明客户端加载、执行或始终遵守规则 |
| 实战案例 | 对应客户端/版本/工作流真实执行、产物与必要回归；有基线的前后对照 | 作者自述、第三方榜单或夹具等于本站实测 |
| 外部优秀案例 | 作者、原日期、原始文章与代码入口；核对可复现条件 | 没有执行却写成本站成功案例 |

无法运行指定客户端时，客户端案例继续待验证。已验证的静态工具可独立作为工具实践发布，标题、摘要、正文均须说清范围，不能借工具测试为未执行的客户端流程背书。付费 API 或外部账号条件不足不擅自购买，也不补造结果。

## 发布与复盘

1. 正文在 `content/`，来源、日期、验证边界贴近相应结论；维护稳定 URL、Frontmatter、首页或列表入口。
2. 执行 lint、build、生成快照审查、内容一致性及必要回归；核对下载内容、本地桌面/手机与关键交互。验证失败不发布。
3. 审查 diff，仅暂存本次文件；遵守分支保护。按同一完整 SHA 分别验证远端、Quality、Workers、新正文/产物和 Sitemap，详见 [发布流程](DEPLOYMENT.md)。
4. 复盘记录选入/淘汰、验证失败与修正、发布证据和未完成；更新 [索引](reviews/README.md)、TOPICS 与 [BACKLOG](BACKLOG.md)。有新信息续写同日报告，不重发同一文章。
5. 发布后 7 天和 30 天回看可得的真实反馈与阅读数据，决定补证据、修订、保留或撤下推荐。不把维护访问算作读者成功；无数据写不可得。

## 每日自动任务

北京时间 09:00 执行维护，20:00 独立核验与复盘；周日同轮加入七日评估与下周三项。使用当前聊天的一项早晚 heartbeat，不另外叠加日更/周报调度。任务以本文件和仓库实际状态为准，触发延迟或遗漏按真实日期记录，不能回填成按时完成。

本地调度依赖电脑开机、应用运行及仓库/网络可用。任务创建成功不等于未来每轮已执行；每轮以实际提交、检查和公开记录验收。
