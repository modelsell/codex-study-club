## 下载响应类型核验与修复

### 读者问题与证据

T21 新下载脚本及 T16 复现脚本沿用稳定的 `/templates/*.py` URL。线上 GET 均为 HTTP 200，字节正确，但多份 `.py` 响应没有 `Content-Type`；同目录 `.json` 响应则为 `application/json`。这不是文件不可访问的证据，也没有真实用户反馈；它确实留下了浏览器、代理和调用方无法依响应头识别脚本文本类型的歧义。

本轮用 Cloudflare Workers 静态资源的 [`_headers` 文件](https://developers.cloudflare.com/workers/static-assets/headers/)为 `.py` 静态资源补 `text/plain; charset=utf-8` 与 `X-Content-Type-Options: nosniff`。官方文档说明 Wrangler 可按扩展名确定 MIME、静态资源目录可用 `_headers` 覆盖默认响应头；Worker 代码直接生成的响应不受该文件控制。本站 `/templates/*.py` 响应此前带有 `CF-Cache-Status` 且从静态资源路径提供，故先以 Cloudflare 本地预览验证，不把文件已返回 200 当作修复证据。

- 修改既有 `public/_headers`，只为 `/templates/*.py` 补充纯文本 MIME 与 `nosniff`；保留原来的 `_next/static/*` 长缓存和指定 `.txt` 附件文件名规则。不改变下载文件字节、URL、HTML 下载链接或 JSON MIME。
