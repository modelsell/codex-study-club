worker 先记录启动与 PID，等待四秒再追加一行。观察器实际看到启动、确认结果尚未存在后才发信号，之后覆盖该等待时间再核对文件；不是取消性能基准。最终脚本五组均执行：

| 对照 | CLI 与实际产物 | 会话工具记录 |
| --- | --- | --- |
| 当前命令未获 Policy 授权 | exit 0、工具事件 error、最终事件 success，worker 未启动、结果 0 行 | 1 条 error |
| 正常执行 | exit 0，结果恰好 1 行 | 1 条 success |
| 只向 CLI 发 SIGTERM | exit 143，退出当时 worker 存活、无结果；观察后 1 行 | 0 条 |
| 只向 CLI 发 SIGINT | exit 130，同样在退出后写入 1 行 | 0 条 |
| 观察器先终止已核归属的 worker 组，再终止 CLI | exit 143，观察后仍无结果 | 0 条 |

SIGTERM 组实际 `--resume latest`，端点仅回固定文本，CLI exit 0；收到的续接历史无函数调用/工具响应，结果仍为原来 1 行。它验证客户端加载与发送历史，没有验证真实模型的续跑决策或重复执行概率。最后一组的清理由观察器额外完成，不能记为客户端自主修复，也不能补回历史。

探索中先后发现：带首锚的 commandRegex 没匹配 JSON 参数；直接 deny 可影响工具可见性；worker PID 不一定是进程组首 PID。分别改为精确 argsPattern、另一命令获准而本命令未授权的对照，以及核对组首命令后再管理该实验组。没有把设置失败当取消结果；最初三组未启动工具的记录不能计为取消复现。最终保留明确的拒绝授权对照，脚本的错误 ZIP 保护也实际以 exit 2 在执行客户端前拒绝。

最终稿脚本为 14905 字节、SHA-256 `c0d97eaed11d47433583bfb48bb5c9c83d6e1b8d926740a3b2bf3294eff1fa87`。草稿分支中的脚本和本地 HTTP 另存版本分别在新目录执行，五组及续接探针通过、两份完整 JSON 相同。输出只有脱敏摘要，未公开 PID、会话、路径、认证头或原始日志。
