## 实际隔离函数对照与边界

在 Node **24.22.1** 使用现有 TypeScript 将上述未改写的固定函数转译后，在只暴露 `exports` 与受限 `require` 的 VM 中执行；唯一运行时依赖只提供 `NodeConnectionTypes.AiTool` 常量替身，类型导入被转译去除。输入为合成预约标识与目标状态。没有载入 n8n 包、引擎、UI 或模型，也没有实际预约对象和业务写入。

| 同一受控工具，改变响应输入 | 实际产生的待执行动作数 | 本层观察 |
| --- | --- | --- |
| 布尔 `approved: true` | 1 | 保留原合成输入，原批准对象不作为工具结果回传 |
| 布尔 `approved: false` | 0 | 返回拒绝说明 |
| 缺少 approved | 0 | 进入拒绝路径 |
| 字符串 `approved: "true"` | 0 | 没有当作布尔批准 |
| 嵌套 data 中的布尔 true | 1 | 产生同一个目标工具的待执行动作 |

五组断言均通过。随后把相同批准输入再交给此函数，仍产生一个相同动作 ID 的待执行请求；这只表明该转换函数自身没有在两次调用之间保存去重状态，**不能推断完整 n8n 会重复执行或缺少幂等保护**。没有运行上游引擎和持久化流程，也没有把“出现一个请求”当成“工具完成一次”。

阶段成果是识别实际节点/源码入口，并完成**固定源码函数的隔离对照**。后续完整工作流需分别观察：待审时业务写入为 0；拒绝后仍为 0；批准后工具实际调用与记录回读匹配；失败、超时、重放及结果未送达时不能误报完成。上述是待执行计划，不能由本次函数断言替代。
