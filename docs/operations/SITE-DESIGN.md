# 网站信息架构与设计约定

更新日期：2026-10-17。本轮由项目负责人明确要求重新规划与设计，不把未排除测试访问的统计当作改版收益证据。

## 要解决的问题

原首页以问答为主，案例分类、案例和全部动态连续铺开；主导航入口过多，手机通过隐藏链接压缩导航。教程从第一章直接开始，没有全局路线。案例库全部展平，缺少搜索与筛选。

新版服务三个任务：第一次开始学习、为手头任务找方法、定位使用中的卡点。

## 页面分工

| 页面 | 职责 |
| --- | --- |
| / | 用途说明、三个起点、六篇精选案例、三条最新动态、模板、问答、社群 |
| /start | 全部教程按准备、任务实践、CLI、工作方式分阶段；章节数来自内容数据 |
| /start/[slug] | 正文、核对日期、章节目录与前后章；末章提供继续实践，不认定读者完成 |
| /cases | 基于标题、摘要、工具、分类的多关键词搜索；分类、结果数量、空状态和重置 |
| /cases#分类 | 保留全部六个已有深链；筛选与 URL hash、前进后退一致 |
| /cases/[slug] | 实践正文、真实核对日期、适用入口、相关案例与下一步 |
| /#ask | 保留流式问答、本地无 Key 回退、引用链接、清空与统计事件 |

其他稳定页面与赞助、主题、互动练习、行业文章仍可由资源菜单和页脚进入。手机导航提供完整入口，不因屏幕宽度隐藏内容。

## 视觉与实现

- 暖白背景、墨色正文、少量陶土橙强调；间距、边框与排版承担层级，避免用大量装饰抢占内容。
- 全局语义 token 维护颜色；新首页、导航、页脚、卡片和学习/案例页面使用 CSS Modules，移除对应废弃全局样式。
- 正文桌面 17px、手机 16px，限制阅读宽度；代码与表格在自身容器内滚动。
- 用服务端组件读取内容；案例筛选仅向客户端传递 metadata，正文仍留在服务端。
- 使用系统字体与现有图标/内容图片，不新增外部字体请求或 UI 依赖。
- 保留键盘焦点、跳至正文、原生菜单、减少动效支持；中文输入法确认候选时不发送问答。
- 同页分类导航使用原生锚点，避免 Next Link 的 pushState 不触发 hashchange 而让 URL 与筛选不同步。
- 行业 iframe 使用 flex 填满剩余视口，避免耦合导航高度。

## 内容与验证边界

文章正文、Frontmatter、来源与稳定 slug 均保留。首页日期表示最近更新，不表示全部文章已经重新核对；案例数量不代表全部经本站复现。UI 文案不能将浏览、翻页或模板下载算作学习完成。

验证覆盖 lint、生产构建、生成快照、站内链接、手机/桌面/横屏布局、分类深链及历史、问答与下载。具体执行结果写入当日复盘。重构通过分支与 PR 交付，推送、CI、部署和公开页面分别核实。
