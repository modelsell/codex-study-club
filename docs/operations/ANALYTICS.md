# 网站统计口径

本项目的 GA4 接入对本地开发、预览、Fork 和其他域名默认关闭。正式域名 `codex.modelsp.com` 使用一个仅限该主机的公开 Measurement ID 兜底，以便没有 Cloudflare Build variable 权限时，Git 集成构建仍能启用统计；`NEXT_PUBLIC_GA_MEASUREMENT_ID` 若被显式配置则优先覆盖该兜底。Measurement ID 不是 API 密钥，浏览器加载 tag 时本来就会公开它。

## 配置与验收

1. 在 Google Analytics 的 **Admin → Data collection and modification → Data streams** 中打开本站 Web 数据流，复制 Measurement ID。Google 的[官方设置说明](https://support.google.com/analytics/answer/14183469)要求使用数据流详情中的 ID，核对日期：2026-10-07。
2. 优先将其他部署的 ID 作为 `NEXT_PUBLIC_GA_MEASUREMENT_ID` 配置；正式站点的公开兜底 ID 已随代码发布，不需要把账号凭据或 API 密钥写入仓库。
3. 重新部署后，在浏览器网络面板或页面源码确认 `googletagmanager.com/gtag/js?id=...` 只在正式域名或显式配置环境出现；再到 GA4 Realtime 报告确认 `page_view`。代码推送、CI、部署和 GA4 收数是四个独立状态。
4. 若要撤回正式站点收集，需要移除正式域名兜底 ID 并重新部署；其他环境删除部署变量即可关闭。空值会让非正式域名组件返回空节点，不会加载 Google 脚本。

2026-10-15 核对 [Google 官方 gtag.js 安装示例](https://developers.google.com/tag-platform/gtagjs)：用普通函数的 `arguments` 对象入队，初始化与事件 fallback 共用 `createGtagQueue`。`npm run test:analytics`（Node.js 22.6+，CI 使用 24）检查命令类型、参数、顺序和原队列保留；不发送网络请求。此前普通数组写法与官方示例不同，这次按标准形式修正，但尚未确认它是否导致数据流未收数。

`data-analytics-ready` 仅表示本地初始化与命令入队，**不表示 Google 脚本加载成功、请求发出或 GA4 已收到事件**。验收依次区分这些状态，并从对应本站数据流读取结果；维护者测试访问不能计为自然增长。

2026-10-15 晚间独立核验：GA4 管理界面的本站 Web 数据流在加载结束后显示“正在接收过去 48 小时内的流量”。这确认后台接收状态，不提供首次收数时刻、事件明细或自然访客数量；尚未建立隔离本站、排除维护访问的完整日期报告。不能由此证明队列修正是唯一原因或网站已经增长。实际时间、口径与后续项见 [当日复盘](reviews/2026-10-15.md)。

- 正式站点的浏览器维护检查先从带 `analytics=off` 的完整地址进入，再核对排除状态；操作和限制见[维护浏览排除](#维护浏览排除2026-11-16)。未标记访问与历史报告不因此变成已清洗数据。
- 2026-10-16 晚间建立按日读取口径：使用本站数据流临时比较、移除“所有用户”，读取中国时间上一完整日历日；切换报告后重新确认比较开关与日期。首次单日样本为 **2026-10-15**：活跃用户 17、新用户 17、事件 92；page_view 40、session_start 22、first_visit 17、user_engagement 10、assistant_question_submitted 3。详见 [当日晚间复盘](reviews/2026-10-16.md)。这组数尚未排除维护和测试访问，不是自然增长基线。
- 每次保留报告日期、时区、采样时间、数据流筛选和测试访问处理状态；若同日数值后续变化，追加复读值，不覆盖原始快照。完整日历日不等于数据已最终处理；排除口径未验证前，不将原数换算为自然用户或增长率。
- 只比较相同口径和完整观测窗口；没有基线不计算增长。
- 页面访问量只能说明页面被请求，不能证明读者完成了案例、获得了收益或解决了问题。
- 运营复盘记录“已配置/未配置、核对时间、可见报告范围”，不记录 Measurement ID、账户信息或原始访问日志。
- 如果未来增加事件，先在本文件写清参数和隐私边界，再实现和验证；不得把文章正文或用户输入作为事件参数。

## 维护浏览排除（2026-11-16）

维护者在打开正式页面前，先使用例如 `https://codex.modelsp.com/?analytics=off` 的完整地址。客户端在加载 Google tag 和初始化事件前检查该值：维护模式不加载 GA 脚本，不将页面浏览、提问、错误或社区点击加入本站事件队列，并设置该 Measurement ID 的 `ga-disable` 标志。这个机制用于减少今后的已标记维护流量；不回删历史事件，也不自动识别全部维护者。

只在同源标签页的 `sessionStorage` 保存一个布尔状态，没有新增用户 ID、Cookie 或服务端过滤。正常存储条件下，去掉查询参数的站内导航和同标签整页访问仍保持维护模式。确认时查看根元素 `data-analytics-excluded="true"`；它仅证明本站客户端应用了排除分支，不是 GA4 报告清洗证明。

`?analytics=on` 清除本功能保存的会话排除状态，恢复进入维护前的 GA 停用值；不会覆盖原有的停用标志。完成维护可直接关闭标签页。普通统计正向对照应在已拦截 Google/模型接口的隔离环境进行，不能把恢复统计后的维护浏览算成自然访问。分享文章使用无维护参数的稳定 URL。

存储被浏览器阻止时，显式 `analytics=off` 与当前文档的客户端导航仍有效；跨整页跳转须再次带上参数并核对状态，不能保证会话持久性。复制或由其他标签打开的页面可能继承初始会话值，正常浏览验证应使用独立上下文或显式恢复。

依据：当日重读 [Google 停用 Analytics 原文](https://developers.google.com/tag-platform/security/guides/privacy#turn_off_google_analytics)（页更新 2026-10-13），要求在 `gtag()` 调用前设置该属性；[sessionStorage 文档](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)（页更新 2026-10-12）解释会话、存储异常与 opener 初始复制。实现和本地/正式验证分别记录于[当日复盘](reviews/2026-11-16.md)。不修改 GA4 账号、共享媒体资源、永久过滤器或既有事件参数。

报告仍要标注：原始日期、读取时间、本站数据流筛选、维护排除实施时间与未覆盖范围。开关上线前数据、未标记维护和其他自动化访问仍不能认定为自然读者；当前也没有可比的已清洗改版前基线或真实任务完成率。
